# EXO 前端控制台

React 18 + TypeScript + Vite 5，连接仓库内独立 Python 后端。生产请求同源 `/api/exo/*`；Vite 将 `/api`、`/admin` 代理到 `127.0.0.1:8000`。

## 启动与构建

```sh
pnpm install --frozen-lockfile
pnpm run dev:demo
```

`dev:demo` 同时启动 Python 模拟后端和 Vite。需要 Python 3.11+；解释器不在 PATH 时设置 `EXO_PYTHON`。模拟配置、任务、表格和日志持久化在仓库根目录 `.local/demo/`，重启后保留。页面明确显示模拟模式，不连接真实外部系统或飞书。

独立启动正常后端：在仓库根目录执行 `python -m backend`，在本目录执行 `pnpm run dev`。正常实例初始为待配置状态，不能直接同步。完整说明见 [后端文档](../backend/README.md)。

```sh
pnpm run typecheck
pnpm test
pnpm run build
```

产物为 `dist/`，目标 ES2020，不含 sourcemap。构建后 Python 后端可直接托管静态产物和 SPA fallback；`pnpm run preview` 只预览静态文件，不提供 API 代理。也可用 npm 执行同名 scripts。

## 八个面板模块

1. 标题与状态：当前同步状态、上次同步时间、日间 / 夜间模式。
2. 同步管理：按日调度周期、带年份确认的应急同步、飞书预警推送开关。
3. 预警配置：多个左闭右开区间（两端相同表示单独一天），新增 / 删除 / 保存 / 取消。
4. 数据总览：最近任务的获取、有效、确认写入、失败数量，以及预警和通知状态。
5. 同步历史：来源、年份、配置版本、阶段、数量、部分失败和恢复入口。
6. 差异详情：已核验的新增 / 更新展示值，分组和分页。
7. 操作日志：持久化审计，级别 / 类别筛选和分页；可修改 INFO / DEBUG。
8. 集成配置：运行模式、外部接口、已有工作流、目标表格、唯一键与受管字段。

## 状态与副作用

- `src/api/types.ts` 为公共契约；后端数据通过运行时守卫校验。应用唯一 `fetch` 点为 `src/api/client.ts`。
- 原有 Context + reducer 管理同步状态、历史、差异和 Tab；配置草稿、日志筛选与提交状态分别由专用 hooks 管理。
- hooks 负责请求与副作用；组件通过回调表达意图。所有请求支持取消与 15 秒超时，`useLatestRequest` 用取消和请求序号防止旧响应覆盖新页面。
- 首次 status / history / config / logs 并行加载。可见页面自动刷新状态和日志；状态变化刷新历史与选中差异。手动刷新同时读取实际配置。
- 配置弹窗创建独立草稿，取消不调用写接口。保存携带打开时的版本；成功采用后端返回的完整配置，409 时保留草稿并提示关闭后重新打开。
- 应急同步提交 `{year}`，历史年份全年，当前年份至当天，采用北京时间。前端展示范围仅作提示，真实范围由后端计算并持久化。
- 推送开关不影响数据同步与预警计算；运行中的任务采用原配置快照。通知失败可在历史中单独重试。
- 差异 summary 是整次任务已确认变化的总数，可用于分页；不展示未确认的写入为成功差异。

## 展示安全与可访问性

全部值作为 React 文本节点渲染，禁止原始 HTML。长值默认截断 200 字符并可展开。错误展示脱敏公共文案，不显示 detail、堆栈或完整原始记录。

仅将明暗主题偏好写入 localStorage，不存认证信息。真实凭据由后端部署环境管理；集成表单不提供凭据输入。

弹窗使用原生 dialog、独立可访问名称、焦点循环、Esc 关闭和关闭后恢复焦点。状态变化通过 aria-live 播报。状态徽标同时使用文字，支持 prefers-reduced-motion。375px 下卡片、历史、差异与表单采用单列布局。

## 部署

内置后端支持构建产物的 SPA fallback、API JSON 404 和静态缓存头。也可以参考 `deploy/nginx.conf.example`。对外部署必须添加 HTTPS 和身份认证；后端框架当前不包含登录系统。允许的反向代理来源通过后端 `--allowed-origin` 指定。详细约束见后端文档。

## 人员看板

`/board` 为人员协作看板，原同步管理页面保留在 `/`。页面使用 `usePeopleBoard` 请求独立的人员名单与分页业务记录接口；API 客户端仍是唯一 fetch 入口，响应经过运行时类型校验，新筛选取消旧请求并防止过期响应覆盖。

看板按业务编号分页，每个编号只显示一行。工作概览展示业务信息与任务统计；展开任务后，独立读取该编号的任务页，每页 5 个任务。同一时间展示一个任务子表；收起后取消请求。记录明细和详情包含 15 个公共字段，任务子表包含 6 个任务字段，合计保留原有 21 个业务字段。

人员筛选匹配创建者或任意任务的主、次负责人，后端按编号去重后分页。创建者默认查看业务下的全部任务；其他参与者默认查看相关任务，可切换到全部。人员颜色由 ID 决定，表格高亮与名单一致。搜索有 300 毫秒防抖，任务按需请求，缓存最多 20 个任务页、有效期 60 秒；重新读取业务页时清空任务缓存。任务错误可单独重试，使用请求取消和序号防止过期结果覆盖。移动端将业务和任务改为紧凑卡片，明暗模式均可用。

## 外观与帮助

界面固定采用 A 静墨蓝，保留日间/夜间模式，明暗偏好在本机保存。旧的外观偏好会自动清理，旧链接中的外观切换参数也会移除。

主导航仅包含人员看板和同步管理；使用帮助位于侧栏底部的辅助区，点击即可打开帮助弹窗。帮助说明人员筛选、记录详情、同步流程和提醒区间；关闭弹窗后保留当前页面及筛选条件，支持 Esc 关闭。旧的 #usage-guide 链接仍可打开帮助。
